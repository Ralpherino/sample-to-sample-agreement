# Sample-to-Sample Agreement Workflow

This repository contains a small ROOT + Snakemake workflow for comparing the distribution of the same branch between two ROOT samples. It was designed for quick validation studies such as MC-vs-DATA, MC-vs-MC, or different processing versions of the same sample.

The workflow reads two ROOT files, extracts the same branch from both trees, optionally applies a common cut, builds histograms using a shared x-axis range, optionally normalizes the histograms, and saves an overlaid comparison plot.

---

## Purpose

The main goal is to automate sample-comparison plots of the form:

```text
sample 1 distribution vs sample 2 distribution
```

for one or more branches and one or more cuts.

Typical use cases include:

- checking MC/DATA shape agreement;
- comparing two MC event types;
- comparing tuples before and after a processing change;
- checking how a cut changes the shape of another variable;
- producing many validation plots reproducibly with one command.

The workflow is intentionally non-interactive. All inputs are controlled from `config/config.yaml`, so it can be rerun and version-controlled cleanly.

The `mc_data_comparison/` directory is generated by the workflow and contains the output range files, intermediate ROOT histograms, and final plots.

## Workflow logic

The workflow is split into three ROOT macro steps controlled by Snakemake.

### 1. `get_range.C`

This script determines the common x-axis range for the selected branch.

It:

1. opens sample 1 and sample 2;
2. reads the requested tree from both files;
3. checks that the requested branch exists;
4. applies the selected cut, if any;
5. finds the minimum and maximum branch values from both samples;
6. adds a small margin;
7. writes the range to a text file.

Example output:

```text
mc_data_comparison/ranges/B_ETA/noCut.txt
```

The range file contains:

```text
xMin xMax
```

This ensures both samples are histogrammed using the same binning and axis range.

---

### 2. `make_hist.C`

This script creates one histogram for one sample.

It:

1. reads the common range from the range file;
2. opens one ROOT file;
3. reads the requested tree;
4. fills a `TH1D` for the chosen branch;
5. applies the selected cut, if any;
6. saves the histogram to an intermediate ROOT file.

Example outputs:

```text
mc_data_comparison/hists/B_ETA/noCut/sample1.root
mc_data_comparison/hists/B_ETA/noCut/sample2.root
```

---

### 3. `plot_mc_data.C`

This script produces the final comparison plot.

It:

1. opens the sample 1 and sample 2 histogram files;
2. optionally normalizes both histograms to unit area;
3. styles sample 1 and sample 2 with different line colors;
4. draws both histograms on the same canvas;
5. uses labels from the YAML config in the legend;
6. saves the final plot as a PNG.

Example output:

```text
mc_data_comparison/plots/B_ETA/noCut/B_ETA_MC_DATA_noCut.png
```

## Configuration

All user-controlled settings are placed in:

```text
config/config.yaml
```

Example:

```yaml
sample1_file: "/eos/lhcb/user/y/yeyang/rds/ap_moreinfopid/MC/v0/truth-matched/rds_preprocess_mc_2012_13266069_magdown_None.root"
sample2_file: "/eos/lhcb/user/y/yeyang/rds/ap_moreinfopid/MC/v0/truth-matched/rds_preprocess_mc_2012_11266009_magdown_None.root"

sample1_label: "MC 13266069"
sample2_label: "MC 11266009"

sample1_tree: "DecayTree"
sample2_tree: "DecayTree"

normalize: true

branches:
  B_ETA:
    bins: 150

cuts:
  noCut: ""
  eta_2_5: "B_ETA > 2.0 && B_ETA < 5.0"
```

### Important notes

- `sample1_file` and `sample2_file` can be any two ROOT files.
- `sample1_label` and `sample2_label` are used in the plot legend.
- `sample1_tree` and `sample2_tree` are the tree names inside the ROOT files.
- `normalize: true` means the histograms are area-normalized before plotting.
- Every branch listed under `branches:` is plotted for every cut listed under `cuts:`.
- Every cut expression must use branch names that exist in both samples.

For example, this cut fails if `B_Y_SEP` is absent in either tree:

```yaml
BYSEP_gt_0: "B_Y_SEP > 0"
```

Before adding a cut, check that the branch exists:

```cpp
DecayTree->Print("*B_Y_SEP*")
```

or more generally:

```cpp
DecayTree->Print("*SEP*")
```

## How to run

### 1. Check the planned jobs

Run a dry run first:

```bash
snakemake -n
```

This prints the jobs that would be executed without actually running them.

---

### 2. Run the workflow

Run with one core:

```bash
snakemake -j1
```

or run in parallel:

```bash
snakemake -j10
```

The `-j` option controls the number of jobs Snakemake may run in parallel.

---

### 3. Rerun incomplete jobs

If a previous run was interrupted, use:

```bash
snakemake --rerun-incomplete -j10
```

---

### 4. Clean generated output manually

To remove all generated outputs:

```bash
rm -rf mc_data_comparison/
```

Then rerun:

```bash
snakemake -j10
```

## Adding more branches

To compare more variables, add them under `branches:`.

Example:

```yaml
branches:
  B_ETA:
    bins: 150
  B_PT:
    bins: 150
  B_ENDVERTEX_CHI2:
    bins: 100
```

Snakemake will automatically produce plots for all branches and all cuts.

---

## Adding more cuts

To compare the same branch under different selections, add more entries under `cuts:`.

Example:

```yaml
cuts:
  noCut: ""
  eta_2_5: "B_ETA > 2.0 && B_ETA < 5.0"
  high_B_PT: "B_PT > 5000"
```

The cut key is used in the output path and filename. Keep cut keys short and filename-safe.

Good:

```yaml
eta_2_5: "B_ETA > 2.0 && B_ETA < 5.0"
```

Avoid:

```yaml
B_ETA > 2.0 && B_ETA < 5.0: "B_ETA > 2.0 && B_ETA < 5.0"
```

## Interpreting the plots

When `normalize: true`, the histograms are scaled to unit area. This means the plot compares the **shape** of the two distributions, not the total number of events.

This is useful for agreement studies because two samples may have different statistics or generated event counts.

When `normalize: false`, the plot shows raw entries. This is useful when the absolute yield difference is meaningful.

## Common issues

### 1. `Bad numerical expression`

Example ROOT error:

```text
Error in <TTreeFormula::Compile>: Bad numerical expression : "B_Y_SEP"
```

This usually means the branch used in the cut does not exist in one or both trees.

Check with:

```cpp
DecayTree->Print("*B_Y_SEP*")
```

### 2. `MissingOutputException`

This can happen if a ROOT macro fails before writing its expected output file. Check the ROOT error printed above the Snakemake error.

Typical causes:

- wrong file path;
- wrong tree name;
- wrong branch name;
- cut uses a branch that does not exist;
- no entries survive the cut.

### 3. Plotting rule cannot find histogram

If `plot_mc_data.C` cannot find `hMC` or `hDATA`, check that `make_hist.C` uses the same histogram names expected by the plotting script.

---

## Current limitations

- The workflow currently saves PNG plots only.
- The output filename still uses `MC_DATA` for historical reasons, even if the comparison is sample-vs-sample or MC-vs-MC.
- The x-axis range is based on the full minimum and maximum after cuts. For variables with strong outliers, a future improvement would be quantile-based range selection.
- No ratio panel is included yet. A ratio plot would be useful for more quantitative agreement checks.

---

## Suggested future improvements

Possible extensions:

- add PDF output in addition to PNG;
- add a ratio panel: sample2 / sample1;
- add quantile-based x-axis ranges to reduce sensitivity to outliers;
- rename output files from `MC_DATA` to generic sample labels;
- save metadata about cuts, branches, binning, and normalization in a summary file;
- add support for weighted histograms.
